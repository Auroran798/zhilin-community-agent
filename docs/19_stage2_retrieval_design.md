# 阶段 2 检索、引用与拒答设计

检索先按角色、小区、适用地域、文档类型、状态、生效日、失效日过滤，再执行向量召回与中文字符关键词召回的混合排序。Chroma 使用持久化集合；未配置真实 Provider 时使用确定性哈希嵌入，仅作为离线演示兜底。生产可通过 `RAG_EMBEDDING_PROVIDER=openai_compatible` 配置兼容 `/embeddings` 的真实嵌入服务。

每条证据都关联文档 ID、标题、来源 URL、发布单位、版本、生效日期、章节/条款和 Chunk ID。回答只能归纳已取回证据，并在响应中给出 citations；未达到阈值则返回“依据不足”，不得编造收费、时间、服务承诺或法律结论。

居民默认只检索有效且适用于本人小区的资料；只有客服/管理员能显式查询历史资料。多来源冲突时保留各自版本和日期并提醒以现行文件为准。
