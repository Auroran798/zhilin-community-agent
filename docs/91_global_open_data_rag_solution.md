# 智邻管家国际公开数据与 RAG 整改方案

## 1. 最终定位

智邻管家是“国际公开数据驱动的完整物业业务 Demo 与 RAG 研究系统”，不是生产物业平台，也不依赖真实小区试点、物业公司授权或国内私有合同/工单数据。

系统同时保留两条严格隔离的数据线：

- **Synthetic Demo**：虚构居民、房屋、账单、公告和业务工单，用于完整演示阶段 1–7 的可写业务闭环。
- **Public Research**：官方公开投诉、违规、检查、楼栋资产及规范文档，用于统计、分类、检索和离线评测；绝不映射成 Demo 居民或真实小区事实。

## 2. 国际数据组合

| 数据包 | 推荐来源 | 在项目中的职责 | 是否可作为 RAG 回答依据 |
| --- | --- | --- | --- |
| NYC Housing | NYC 311、HPD Complaints、HPD Violations | 维修分类、状态生命周期、风险等级、案例分布 | 业务记录否；官方法规/说明页可以 |
| Singapore HDB | Property Information、Existing Building、Branches、Car Park | 楼栋、地址层级、分支机构、停车场等资产主数据 | 数据字典可引用；不能推导物业规则 |
| UK Complaint Governance | Housing Ombudsman Complaint Handling Code | 投诉受理、分级、时限、补救、复盘流程 | 是，但仅适用于 UK 对应范围 |
| US HUD Inspection | Multifamily physical inspection scores | 检查评分、风险看板、抽样与趋势分析 | 评分记录否；官方检查说明可以 |
| Open311 | GeoReport v2 | 统一跨城市服务请求字段与状态语义 | 仅作为接口规范依据 |
| China property/fire safety | 国务院、住建部、应急管理部、北京/上海政府 | 物业管理、装修、维修资金、消防、报修与投诉 | 是，仅按全国或城市辖区回答 |
| Australia rental/strata | NSW Fair Trading、Consumer Affairs Victoria | 租赁维修、共用区域责任、投诉、调解与灾害处置 | 是，仅按州回答 |
| New Zealand tenancy | Tenancy Services / MBIE | 维修责任、14 日整改通知、健康住宅、灾害处置 | 是，仅适用于新西兰 |

纽约数据是当前主业务数据骨架：仓库的受控快照已经取得 50,000 条 HPD 维护投诉和 10,000 条住房违规记录，并记录官方 URL、许可条款、字段最小化、校验和与下载清单。新增数据源必须复用同一套 manifest、隐私最小化和独立 schema 规则。

## 3. 知识库分区

| 分区 | 内容 | 允许参与生成回答 |
| --- | --- | --- |
| `KB_POLICY` | 官方法律、法规、投诉处理规范、检查说明 | 是，必须匹配 jurisdiction 与有效版本 |
| `KB_PROCEDURE` | 官方服务流程、API 规范、公开办事指南 | 是，必须说明适用范围 |
| `OPS_OPEN` | 311/HPD 工单、违规、检查和资产记录 | 否，只做统计、分类、合成和检索实验 |
| `DEMO_SYNTHETIC` | 虚构小区制度、公告、账单和业务数据 | 仅限 Demo Garden，必须标记 synthetic |
| `EVAL_GOLD` | 独立人工审阅的查询、证据与拒答标签 | 否，只用于评测 |

不得把海量投诉记录直接切块后当作“知识”。一条投诉只能说明曾有记录，不能证明通用规则、当前状态或另一个小区的事实。

## 4. 地域与语言硬规则

每个知识文档和切块至少带有：`jurisdiction`、`language`、`source_type`、`authority_status`、`version`、`effective_date`、`expiry_date`、`license`、`answerable` 和 `checksum`。

查询顺序固定为：确定 jurisdiction → 过滤同地域有效文档 → 混合召回 → 重排 → 生成带来源回答。若知识库同时存在多个国家/城市，而请求未选择 jurisdiction，系统拒绝给出规则性结论并要求选择地域。中文问题可以召回英文原文，但中文译文只是派生文本，引用必须落到官方原文。

## 5. RAG 技术方案

1. **解析**：优先保留标题层级、条款、页码、表格和原文链接；扫描 PDF 使用 PaddleOCR，复杂文档可用 Unstructured。
2. **索引**：Demo 默认 hash 仅用于无模型的自动化回归；正式多语种实验必须比较 BGE-M3 与 Qwen3-Embedding，并记录模型、维度与数据快照。
3. **检索**：BM25/全文检索与 dense 向量并行，用 RRF 融合；再用多语种 reranker 精排。PostgreSQL 运行模式使用 pgvector，并先做 jurisdiction、document_type、有效期和权限过滤。
4. **生成**：只允许使用最终证据；回答逐条附文档、版本、地域、条款/章节和原始 URL。证据不足、地域不明、版本冲突或问题要求个案承诺时拒答。
5. **版本**：当前版本默认可见；旧版本切块不可删除，只有经理/客服显式 `include_history` 时可检索，引用展示切块自身版本。

## 6. 数据规模与评测

“文档越多越好”不是目标。当前登记 28 份真实官方文档和 6 份合成制度，其中 22 份官方材料可以由精确主机白名单与 manifest 重建；71,200 条公开业务记录仍不计入知识文档数量。当前覆盖足以做受控回归，但不足以证明正式多语种语义质量。

建议完成规模：

- 100–250 份经过登记的官方政策/流程文档；
- 5,000–15,000 个结构化、去重、带地域和版本的知识切块；
- 20,000–100,000 条公开业务记录保存在关系型研究数据层，不进入回答语料；
- 500–1,000 条中英文独立金标查询；当前 128 条固定回归集只用于工程回归，覆盖正常回答、跨语种、时效冲突、地域冲突、越权、注入和拒答。

数据集按来源、版本与时间切分，禁止用同一模板改写成训练集和测试集。核心门槛为 Recall@5 ≥ 0.92、引用正确率 ≥ 0.98、拒答 F1 ≥ 0.95、地域泄漏为 0；Ragas 的 faithfulness/context 指标只作为辅助，不能替代人工来源核对。

## 7. 完成标准（无试点版）

项目完成不要求真实物业接入或用户试点，必须同时满足：

1. 所有国际数据源有官方 URL、许可、获取时间、字段清单、快照校验和和数据卡。
2. Demo 合成数据与公开研究数据物理/逻辑隔离，公开案例不会进入小区账单、工单或 Dashboard 业务指标。
3. jurisdiction 缺失或冲突时不输出混合规则答案；历史版本可审计、可受控检索。
4. 使用真实多语种 embedding 的离线评测达到门槛，hash fallback 的结果不得作为 RAG 质量证明。
5. 一条命令可以重建数据、索引、评测和报告；测试、安全扫描和迁移检查全部通过。

这组标准以“可复现、可追溯、可比较”替代真实试点，符合课程项目、暑期实践展示和技术研究用途。
