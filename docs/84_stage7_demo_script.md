# 阶段 7 最终 Demo 脚本（约 10 分钟）

1. 0:00–0:30：展示首页、四种 Demo 角色和项目数据边界。
2. 0:30–2:20：居民输入“3栋电梯经常卡住”。展示 Agent 信息采集/确认、工单、确定性 SLA 与时间线。
3. 2:20–3:10：客服查看派单建议；说明技能、服务区域、负载和可用性排序。由客服人工确认派给维修员。
4. 3:10–3:50：维修员开始处理、提交结果；居民确认完成并评价。
5. 3:50–5:10：经理输入“帮我写一份明天下午3栋停水维修通知”。展示草稿、人工提交审核、批准、发布；切换居民通知中心并标记已读。
6. 5:10–6:30：居民询问“为什么我这个月比上个月贵”。展示账单明细、确定性差异项、费用复核申请和客服处理结果。
7. 6:30–8:10：经理展示消防巡检计划并执行演示调度。巡检员提交异常；创建、派发整改；维修提交结果；经理人工复查关闭。
8. 8:10–8:45：进入设备台账，打开关联电梯/消防设备的工单、巡检和整改历史。
9. 8:45–9:20：展示 NYC Public Real 页面，明确说明其为脱敏历史公开监管记录，与本小区数据独立。
10. 9:20–10:00：展示经理 Dashboard、审计记录、MCP/Harness 工具目录和测试结果。

演示时应明确：不展示真实住户信息、不触发真实支付或设备控制；公告发布必须经人工审核，重大安全整改必须经经理复查。
